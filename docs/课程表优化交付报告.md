# 课程表页面重构与性能优化交付报告

## 范围与结论

在原有课程表页面上替换布局与分段控件，保留周次操作、课程详情、今日安排、学期数据、明文优先导入、base64 兼容与原子持久化。没有修改工程配置、工作流、忽略规则或资源目录。

代码已消除下述可从源码确认的重复开销。没有运行 iOS 实机或 Instruments，因此本文不将这些开销断言为唯一的掉帧根因，也不声称已达到 60/120 FPS 或实测无回归。

## 1. 原实现中的性能风险与证据

基线为提交 `218b3226fb11da3085cd4f82aa3f959630df766a`：

| 位置 | 代码事实 | 影响 |
| --- | --- | --- |
| `ContentView.body` | 整个页面包在一分钟周期的 `TimelineView` 中 | 时钟变化使周网格也进入更新范围 |
| `TimetableStore.refreshToday` | 即使周次相同也对 `@Published week` 赋值 | 增加订阅视图失效的机会 |
| `WeekGrid.dayColumn` | 每次生成列时调用 `doc.lessons`，随后建立 `DayLayout` | 在视图计算中重复筛选、排序和冲突布局 |
| `TimetableDoc.date/monday/startDate` | 每次日期查询进入 `parseDate` 并新建格式器 | 各列渲染重复解析同一学期起点 |
| `TodaySnapshot` | 多个计算属性重复调用 `lessons`、过滤、排序和时间解析 | 同一个今日卡片可能重复处理相同数据 |
| `TimetableStore` | 文件读取、解码、验证、编码和写盘同步发生在主执行器 | 大文件导入及启动时可能阻塞界面 |
| `ContentView`、`WeekGrid` | 外层纵向滚动内嵌横向滚动，固定 132 列宽、144 行高 | 无法整周横向总览，形成额外布局与手势复杂度；未断言嵌套本身必然掉帧 |

原来的课程 ID 已稳定，未把它误报为问题；原实现没有昂贵阴影，也未为此添加合成缓存。

## 2. 优化措施

- 新增 `ScheduleIndex`：读入数据时预计算课程短地点、节次文字、配色索引、钟点区间，并按日排序。
- 只维护一个当前周快照与一个今日快照。周过滤及冲突区间分组不再位于 View body；切换卡片/列表直接复用同一 `WeekPresentation.days[].lessons`。
- 没有无限增长的按周缓存，没有随机 View ID，也没有滚动偏移状态监听。
- 周次未变化不发布新快照；仅在跨日、时区变化、数据替换或周次变化时更新相关展示数据。
- 分钟时钟下沉到 `TodaySummaryView` 和今日安排弹窗，周网格不随每分钟定时器重新筛课。
- 文件读取、JSON/base64 解码、验证、索引建立、编码和写盘放在后台任务。主执行器负责发布状态；忙碌标记防止重复导入或恢复。
- 普通布局只允许课表区域纵向滚动；短容器或辅助功能大字体时改用单一整页纵向滚动，不嵌套两个纵向滚动器。
- 列表使用 `LazyVStack`，分组 ID 为星期，课程 ID 沿用文件稳定 ID。
- 翻周不再把整张网格置于全局动画事务中；模式过渡与选中指示器动画分别限定作用域。

## 3. 自适应布局

容器来自导航栏、安全区域之内的 `GeometryReader`。普通布局先让今日区域和周次控件占据自身所需高度，再将实际剩余尺寸交给课表。没有读取设备型号或物理屏幕分辨率，没有几何测量结果写回状态的反馈环。

设容器宽高为 `W/H`，大节数为 `N`，间距为 `g=3`，节次栏宽为 `R`，星期表头高为 `D`：

- 七列等宽：`column = (W - R - 7g) / 7`。
- 基础行高：`row = clamp(floor((H - D - g - (N-1)g) / N), minimum, maximum)`。
- `minimum` 随 Dynamic Type 增长，至少 52 pt；`maximum` 至少 100 pt，不能小于 minimum。
- 课程高度：`row × span + g × (span - 1)`。
- 课程纵向偏移：`startBlock × (row + g)`。
- 超出可用高度时纵向滚动，七列仍保持完整横向显示。

默认正文卡片字号不小于 12 pt。卡片行数、内边距和次要地点信息按可用空间决定；极大字体在七列中的字号以上限列宽约束，列表仍使用完整系统动态字号。极窄列使用单字星期标题，VoiceOver 保留完整星期名称。课程详情始终提供完整信息。

原六大节数据无需修改。数据格式和字段不变，只将大节数量及跨度检查改为根据 `blocks.count` 判断，支持其他学期的大节数量。

真实冲突采用明确提示方案：先按周过滤，再合并有重叠的连续区间。相接但不重叠的课程分开显示。冲突块覆盖该组的区间并集，显示警示图标和课程数量；点击显示全部课程各自的真实节次、时间与详情入口。列表始终逐条展示所有课程，不漏课。

## 4. 模式切换动画

阅读并参考 [smooth-option-switcher Skill](https://github.com/zhoulinhua0-star/smooth-option-switcher/blob/main/skills/smooth-option-switcher/SKILL.md) 与其 `references/README.md`、`production.md`、`example.html`、`styles.css`、`verification.md`。

采用该参考的平面双选项改编，非嵌套套餐控件的逐像素复刻。没有引入 HTML、CSS、JavaScript 或 WebView。

`ViewModeSwitcher` 用等宽原生按钮和一个常驻圆角指示器。指示器宽度为轨道一半，通过 `offset` 在两个端点移动；`spring(response: 0.28, dampingFraction: 0.94)` 提供克制的运动。指示器不随选择销毁重建，反向点击可以重定向动画目标。

内容仅使用 0.16 秒 opacity 过渡，周次不变。系统 Reduce Motion 开启时禁用位移和淡入淡出动画事务。按钮保留原生焦点、最小 44 pt 高度及选中辅助功能特征；模式通过 `AppStorage("scheduleViewMode")` 保存。

## 5. 稳定配色

颜色池包含蓝、紫、薄荷绿、奶油黄、粉、橙、青绿、薰衣草八组。浅深色分别指定背景及文字色，静态构造并复用。

课程键优先采用 `courseCode`，因为现有数据中同一课程在不同星期的排课 `id` 不同；缺少课程编号时使用课程名与教师名，并进行 Unicode 规范化。固定 FNV-1a 哈希映射至八组颜色，只在索引构造时生成颜色索引。

不使用 `hashValue` 或渲染时随机数。颜色不依赖周次、视图模式、课程排列或进程。八色池减少三色池的碰色概率，但不能保证每对相邻课程都异色；为保证跨会话稳定，不按临时相邻关系重新分配。课程名称与时间信息仍是识别依据。
